P14 S4 步骤 17k：宿主接口 H 改走 provide/inject（组件不再 import 模块级 H）

13 个组件文件都 import { H } from './vue.js'，而 H 是 vue.js 里的模块级 let，由 app.js
在模块初始化期 setHost({...}) 赋值。组件对「谁先跑、谁赋值」一无所知，只能赌挂载时它已经
装好了（旧注释里就是这么写的）。这份隐式依赖还堵死了拆 god-object 的路：123 个 H.xxx 想按
用途拆成细粒度 provider，组件就得逐个改 import。

- vue.js 加 HOST_KEY + withHost(app)（app.provide('H', H)），三个挂载点各调一次：
  mountView / mountSheet / shell.js 的 mount（外壳树含 <teleport> 里的进度层）。
- 组件里 const H = inject('H') 写在 setup 体首行，模板一行不改（模板里的 H.xxx 读的仍是
  setup 返回的那个 H）。共 47 处 setup，13 个文件的 import 行去掉 H、解构行加 inject。
- 改造是脚本做的（.test/to_inject.py）：先把注释与字符串内容掩码成空格，再配对括号找
  setup 体，只对引用了 H 的 setup 注入（单行体插一行内，多行体按原缩进换行）。掩码这步
  是必须的：setup( 在注释里也出现（「setup() 返回里暴露 H」），不掩码会把注释当代码配对
  括号，直接 unbalanced。
- 闸门⑮ 扩 3 条（三条都反向验证过会红）：a) 组件文件不许再 import { … H … }；
  b) setup 里出现 H 就必须 inject('H')（漏了是 ReferenceError，整模块不执行 = 白屏）；
  c) 三个挂载点必须 withHost(app)（漏了 inject 拿到 undefined，模板里 H.xxx 全炸）。
- 收益：依赖摆到明面上 —— 装配哪个 app 的人负责提供宿主一目了然；测试可以 provide 一个
  假宿主只挂单个组件；后续拆 H 只动三个挂载点，组件模板不动。

  FWADDRT，与本次改动无关，重跑即过）、三套 DOM 等价全部一致（dom_equiv3 含进度层整张卡 /
  dom_equiv2 / dom_equiv card 2495 B、todoRow 651 B、todoTx 454 B）。
