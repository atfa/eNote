S4 步骤 17a：调试基建（Vue dev 构建 + ?vue=dev + Chrome inspect）

新阶段 P14 的起点。用户问「Vue 到底有什么好处」，先盘了使用量：live() 120 处 vs
reactive 3 处、watch 0、<transition> 0、<Teleport> 0、provide/inject 0 —— 只用了
模板+组件这一层，响应式那层被 V.tick++ 大锤绕过去了。P14 顺序：调试基建 → 真响应式
→ Transition → Teleport → provide/inject → Vant（像素会变，开工前问用户）。

17a 是第一步，为后面五条铺路：

- vendor Vue 的 dev 构建 vue.global.js（612 KB，同版本 3.5.46，sha256 进 VENDOR.md
  新增的表）。实测 prod 构建里 __VUE_DEVTOOLS_GLOBAL_HOOK__ 出现 0 次、dev 版 1 次，
  这就是「调试必须换文件、不是加开关」的根据。
- index.html 新增 id="vue-select" 内联脚本：?vue=dev 或 localStorage enote.vue=dev 时
  加载 dev 版。document.write 解析期同步插入，保证早于 <script type=module>（js/vue.js
  模块求值时就要拿到 window.Vue）。
- MainActivity：setWebContentsDebuggingEnabled(true)（chrome://inspect 入口）+ 私有目录
  里有 enote/.vuedev 时自动带 ?vue=dev。开关刻意与 jseval 的 .devmode 分开：测试工具每次
  都建 .devmode，共用会让 test.sh 跑成 dev 版 Vue，165 项基线就没得比。
- 为什么值得多带 612 KB：运行时警告只在 dev 版里。16d 真机抓到的裸 <ico> 在 prod 完全
  静默；dev 模式下 probe 挂一个未注册标签，testlog.txt 立刻出现
  [Vue warn]: Failed to resolve component: nosuchtag。
- 闸门：ui_test.js 新增 ㉕（共 122 项）；go/web_test.go 的 TestVendorHashMatchesDoc 改成
  逐文件核对 sha256 并钉住「dev 有 hook、prod 没有」；首页内联脚本白名单从 1 个放宽到
  2 个（probe + vue-select），ES5 检查对两个都跑。
- README 新增 §5.2：dev 模式两条路 + adb over WiFi + chrome://inspect + Vue Devtools 步骤。

验收：ui_test 122 项全绿、GO_TEST=1 ./build.sh 绿、./install.sh Success、真机双模式 probe
各一次（prod vue.global.prod.js/dev=false，dev vue.global.js/dev=true，dev 启动日志有
"You are running a development build of Vue."）、test.sh --vd 166 ok / 0 FAIL / PASS。
