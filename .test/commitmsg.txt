结构：标题走 #title 插槽（内容仍是 <h3 id="dlgT">）、按钮走 #footer 插槽（.dacts + .btn /

:show-confirm-button="false" + :show-cancel-button="false" 关掉。读渲染函数确认的两件事
（文档里没写）：footer 插槽无条件渲染，不受这两个开关影响；close-on-click-overlay 在
van-dialog 里默认 false，旧版点遮罩是取消的（@click.self），必须显式打开并接
@click-overlay="H.dlgCancel()"（Vant 自己只把 show 置 false，不会调 onCancel 回调）。

tokens.css 映射表：宽度 min(400px, calc(100% - var(--s5) * 2)) —— 必须同时给
--van-dialog-small-screen-width，否则窄屏被 @media (max-width:320px) 覆盖；背景/圆角/

（Vant 在这里写死 var(--van-text-color) = #323233，深色主题下会糊成一片）。

真机计算样式对比（.test/p18dlg.js + .test/dlgcmp.py，基线 vs 新）：正文 / 取消 / 确定 /
标题 零差异；盒子那几处是定位方式换了（fixed + transform 居中 vs flex 居中），视觉 top

最大的收获是踩出来的：第一版在虚拟屏上「对话框弹出来看不见、点取消关不掉」，test.sh --vd
从 164 掉到 155。根因不在我们的 CSS，在 Vue —— van-popup 的显隐是 Vue 的 <Transition>
驱动的，enter() 与 leave() 都在 nextFrame（双 requestAnimationFrame）里起跳。Chrome 不给
「不可见窗口」出帧，rAF 就不跑，于是 enter-from 类永不摘除（van-dialog-bounce-enter-from
的 opacity:0 永久留着 → 弹层全透明），leave() 永不结束（display:none 永不落下 → 关不掉、
遮罩留在屏上）。真机前台不受影响，虚拟屏必踩，息屏时后台弹出的对话框是同一类场景。
CSS 时长归零救不回来：探针实测 leave 期间 animDur=0s animName=none transDur=0s op=1
disp= —— 时长已经归零，节点仍关不掉，因为 Vue 连 getTransitionInfo 都放在 nextFrame 里。

改法：显隐退回 v-if + :show="true"（ToastHost 同步改，18b 是同一隐患）。「对话框在不在」
是状态的纯函数：创建即可见、销毁即消失，Vant 那些 van-fade-* / van-dialog-bounce-* /
van-popup-slide-* 类一个都不出现（transitionAppear 默认 false，挂载不走 appear 过渡），
入场动效由 .enote-dialog / .enote-toast 上的 pop 关键帧提供（CSS 动画走合成器，不经过
Vue）。代价是节点随开合创建/销毁，静息态没有 #dlg / #toast —— 测缝契约改成「先弹一个再读」
（新增 seam dlgseen=1 断言），与 17i 的 #sheet、18b 的 #toast 完全同构。views/shell.css
与 js/shell.js 各留一段注释，防止以后有人把 v-if 改回 v-model:show。

test.sh：三处对话框轮询（设置页清空、笔记删除、附件删除）从「.on 类」改成「offsetParent
可见性」判定，对旧实现和新实现都成立；测缝补开合一次对话框。闸门两处：⑥ 的选择器
.dlg .dacts .btn{ → .dacts .btn{；「var() 解析不了」那条把 vendor/*.css 的 --van-* 定义
也算进 defined 集合（否则 var(--van-text-color) 被报成整条声明失效）。
