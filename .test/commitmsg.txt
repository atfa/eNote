P14 S6 步骤 20：设置页六个输入框的值搬进状态（SFORM）

步骤 19 之后继续。saveSettings() 是全站最后一处「把 DOM 当用户输入的真相源」：
$('#sUrl').value.trim() 连读五个输入框，Vue 那一侧完全看不见正在打的东西。后果都写在
旧注释里 —— settingsRefresh() 专门警告「重建会把输入框里正在打的字清掉」，夹具想改一个
字段只能写 DOM，探针也读不到表单当前值。

改法
- app.js 加 var SFORM = Vue.reactive({ v: null }) + formFill()（从 S.settings 灌初值，
  打开设置页时调用，保存成功后用服务端回包重灌）+ formInput(k, v)（逐键写）。
- settings.js 的六个输入框改成 :value.attr="f.xxx" @input="H.formInput('xxx', $event.target.value)"，
  f 是 computed(() => H.SFORM || {…默认值})。宿主接口加 get SFORM() / formInput，
  HOST_KEYS['sheet:settings'] 22 → 24 个 key。
- 为什么不用 v-model：v-model 写的是 DOM property，序列化出来没有 value 属性，而 #sUrl 的
  value 属性是 test.sh 钉住的契约（urlAttr=1，它同时保证「新建 input 的初值从属性来，
  保存不会存空值」）。:value.attr + @input 是同样的双向效果、属性真的在 DOM 上。
- 顺带修掉一条过时注释：settingsRefresh() 只重画不重建的真原因不是「丢正在打的字」
  （值在 SFORM 里，重建不丢），是重建会打断 Android 输入法的组合中状态（拼音打一半被吞）。
- 签名断言 id="sKey" :value.attr="s.apiKey || ''" 改成新绑定；闸门仍 122 项。

（toast「已保存」、S.settings.model 回读一致）→ 关掉重开显示保存值 → 复原为 exec。
